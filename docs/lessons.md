# 今回の学び(実在の建物を Blender のスクリプトだけで再現する)

花園ラグビー場を作って得た進め方、つまずき、直し方をまとめる。別のモデルがこれを読んでスキルにできるよう、
なぜそうしたかと、そのまま使えるスクリプトの場所を書く。書いた日: 2026-11-17。
環境は Blender 5.3.0(画面なし)、Mac M4・メモリ 16 GB・Metal の GPU、ffmpeg。

## 1. うまくいった進め方

### 1-1. 先に「測れる資料」を作る
- 公式の寸法はほとんど公開されていなかった(席数、照明の台数、映像装置の表示面の大きさだけ)。平面は **国土地理院のシームレス空中写真**(ズーム 18、1 画素 約 0.49 m)と **OpenStreetMap の外形**から自分で測った。
- 空中写真はグラウンドの長辺がまっすぐになるよう回し、**原点から 10 m ごとの目盛りを重ねた画像**(1 m = 5 画素)を 1 枚作った。以後の寸法読みはすべてこの 1 枚でできた。
- 縮尺の確かめに「規定で決まっている長さ」を使う。今回はゴールポストの間隔 100 m が写真で合っていたので、目盛りを信用できた。
- なぜ: 写真を眺めて数字を当てるより、目盛りつきの 1 枚を作るほうが速く、あとで何度も見返せる。

### 1-2. 高さは「大きさのわかっている物」を物差しにして写真から測る
- 高さの公式な数字はなかった。**表示面の縦が 8.16 m とわかっている映像装置**を物差しにした。
- 手順: 写真の中で物差しの画素数から焦点距離(画素)を出す → 地平線の位置をカメラの高さから決める → 測りたい点の高さ = (地平線 − その点の y)÷ 焦点距離 × 距離 + カメラの高さ。
- 2 枚の別の写真で同じ値が出るかを確かめる。照明塔は最初の見た目の見積もり 48 m が、この方法で 37 m になった。
- 物の平面の位置も同じ写真から出せる(画面の左右の位置 → 方位 → 空中写真の候補と突き合わせる)。照明塔の位置はこれと空中写真の両方で一致した。

### 1-3. 真上からの正射影を空中写真に重ねて、外形を確かめる
- `cameras.make(scene, "map")` は、空中写真と同じ縮尺・同じ向きの正射影カメラを作る。描いた画像を ffmpeg で半透明にして重ねる(`out/stage3/map_overlay.jpg`)。
- スタンドの大きな形を作った直後にこれをやると、位置のずれが 1 回で見つかる。

### 1-4. 寸法は 1 つの JSON、形はそこから計算する
- `config/dimensions.json` に全部の数字を置き、`scripts/hz/config.py` で読む。JSON にしたのは Blender の外の Python からも読めるため。
- スタンドの断面は「前の壁の高さ+区間の列」で書いた。区間は `["rows", 段数, 奥行, 蹴上げ]`、`["flat", 幅]`、`["rise", 高さ]`。`layout.treads()` が踏み面の一覧に直し、**躯体、座席、通路、手すり、出入口が全部この同じ一覧を使う**。段数を 1 つ変えれば全部が追従する。
- 段数は「公式の席数 ÷(列の長さ ÷ 席の幅 0.48 m)」で逆算し、実測した奥行に収まるかで確かめた。作った席は合計 21,555、公式の一般席の合計は 21,538。

### 1-5. スタンドごとの局所座標と回転行列
- 局所座標を (u=左右, d=グラウンドから外へ, z) とし、`util.stand_xf(side, wall)` で世界座標に直す。**回転と平行移動だけ(鏡映なし)**なので面の向きが保たれ、4 つのスタンドを同じコードで作れる。
- 面を置く向きは `util.frame_xf(origin, normal)`(x=右、y=上、z=法線)。照明塔の枠、映像装置、傾いた投光器に使った。

### 1-6. 面をためて 1 つのメッシュにする道具(`util.MB`)
- `box / rect / prism / sweep_u / cyl / bar / face` を持ち、`build()` で 1 オブジェクトにする。トラスの丸棒 数千本でも組み立ては 0.1 秒以下。全体の組み立ては約 1 秒(約 28 万面)。
- 組み立てが速いので、**毎回最初から作り直す**やり方で困らなかった(部分だけ作り直す仕組みは要らなかった)。

### 1-7. 座席は「点の上に並べる」
- スタンド×色ごとに頂点だけのメッシュを作り、`instance_type = "VERTS"` にして、席の形のオブジェクトを子にする。親の行列をスタンドの回転にすれば席の向きも合う。
- 色は点の集まりを色ごとに分けるだけ。客席の文字は、(u, d) が文字の線から一定の距離の中にあるかで判定した(`seats.letter_test`)。

### 1-8. 昼と夜を 1 つの .blend で切り替える
- 夜だけの光源は名前が `night_` で始まるコレクションに入れる。光る面は `materials.emissive(name, color, day, night)` で作り、マテリアルに昼と夜の強さを持たせる。`sky.setup_day / setup_night` が描く直前に切り替える。

### 1-9. 見比べのやり方
- `scripts/compare.py` に、参考写真ごとの(カメラ位置、見る先、焦点距離、縦横比、昼夜)を表で持ち、描いて ffmpeg で左右に並べる。
- **並べた画像を自分で開いて、違いを言葉で書き出し、大きい順に直す**。1 回目で 10 点、2 回目で 2 点直した。
- 比較に使う写真は Wikimedia Commons のものだけにし、作者とライセンスを API で取って README に書いた。

### 1-10. 進み具合の記録
- `PROGRESS.md` に「終わったこと、今やっていること、次にやること、わかっている問題」を書く。
- **反省**: 途中で更新をさぼり、⑤の時点のまま⑨まで進めてしまった。再開のときに古い記録を読ませることになった。段階のコミットと同じ操作の中で必ず更新する。

## 2. つまずいた所と直し方

| つまずき | 原因 | 直し方 |
|---|---|---|
| `instance_type = "VERTICES"` でエラー | Blender 5.3 の値は `"VERTS"` | エラー文に使える値が出るので、それに合わせる |
| 空のテクスチャの太陽の向きがわからない | `sun_rotation` の決まりが資料にない | 全天のカメラで小さく描いて一番明るい画素を探した。結果: +Y から +X へ回る角。`rot = atan2(v.x, v.y)` |
| 赤い座席が日なたで桃色になる | AgX の標準の見た目は明るい赤の彩度が落ちる。照りも強かった | 見た目を `"AgX - Punchy"` に、粗さ 0.6・スペキュラ 0.3、露出を下げた |
| 見た目(look)の名前が列挙に出ない | 静的な列挙は `NONE` だけ。実際は表示変換ごとに違う | 文字列で直接入れて try で受ける。AgX は `"AgX - Punchy"` など、Filmic は `"High Contrast"` など |
| 夜が真っ白 | 面の光の強さが 30 倍ほど強すぎた | 塔の光 6e4 W(18×5.6 m)、屋根の区間 1.4e4 W で落ち着いた |
| 夜の芝が白っぽい | 低い角度の光でスペキュラが効く | 芝の粗さ 0.9、スペキュラ 0.04 |
| 画像が真っ黒、または梁や壁しか写らない(4 回) | カメラが躯体・屋根のトラス・柱の裏・出入口の箱の中にあった | カメラは「その場所の踏み面の高さ+1.2〜1.6 m」で置く。`roof.ground_z(d)` や `layout.treads()` で床の高さを出す。柱と出入口の u を避ける |
| 参考写真の撮った場所を取り違えた(南西と思ったら南東) | 屋根つきのスタンドがどちら側に写るかを確かめなかった | 「北を向くとメインスタンド(西)は左」のように、写っている物の左右から場所を決める |
| 遠くの山が見えない/大きすぎる | 実際の距離と高さで置くと、スタンドに隠れるかどうかが微妙 | 写真で「スタンドの上にどれだけのぞくか」を角度で測り、それに合う距離に板を置いた(実寸ではないと docs に書いた) |
| 光のにじみが効かないように見えた | しきい値が高く、効き目が小さかっただけ | しきい値を極端に下げた画像と比べて、効いていることを確かめてから調整した。5.x は `scene.compositing_node_group` に CompositorNodeTree を入れ、Glare の設定は入力ソケット(`Type`、`Threshold`、`Strength`、`Size`)で行う |
| 最初の描画だけ 3 分以上かかる | Metal のカーネルの準備 | 1 回きり。2 回目からは 1600×900・48 サンプルで 5〜10 秒 |
| 夜の外観の 4K が 1 枚 47 分 | 原因は未確認(街灯の点光源 10 個か、Mac のスリープ) | 長い描画は `caffeinate -i` をつけて流す。直ったかは未確認 |
| web-fetch が PDF の本文を読めない | 取得した PDF は保存されるが、要約に本文が入らない | 保存されたファイルを Read で直接開く |
| システムの python3 に PIL がない | — | 画像の結合・回転・切り出し・重ね合わせは ffmpeg の filter_complex で済ませた |
| Bash の cd で作業フォルダが動く | — | 毎回 `cd "<プロジェクトの絶対パス>" &&` を先頭につける |
| sed や python で書き換えたファイルを Edit できない | 道具が「読んでから編集」を求める | 小さな置き換えは python の `str.replace` でまとめて行い、置き換え前の文字列があるかを assert する |

## 3. 判断とその理由

- **形は全部ジオメトリ、模様はマテリアル**: 芝の縞、コンクリートのむら、正面の菱形のタイル、広場のレンガは位置から計算するノードで描いた。メッシュが軽く、縞の幅などを数字 1 つで変えられる。
- **投光器 381 台を 1 台ずつ光源にしない**: レンズは光る面にして見た目を作り、照らす役は塔ごと・屋根の区間ごとの面の光 1 枚に任せた。ノイズが少なく速い。光源は `visible_camera = False` にして四角が写らないようにする。
- **図面のない複雑な外装は「遠目の印象」を優先**: 斜めの帯は 2 組の格子を半周期ずらして重ね、タイルは乱数。実物どおりではないと残った違いの一覧に書いた。
- **実在の企業名は使わない**: 看板は競技の用語から作った名前にし、名前の一覧を 1 か所(`signage.NAMES`)に置いた。
- **周りは粗くてよいが、無いと困る**: 地面、家並み(乱数の箱)、木、山がないと、空からの絵と一周の動画が成り立たない。色は建物より地味にする(最初は白すぎて主役より目立った)。
- **確認用は小さく速く、仕上げだけ重く**: 確認は 1600×900・48 サンプル・JPEG。仕上げは 3840×2160・160〜200 サンプル・PNG。
- **動画は 1 コマずつファイルに書く**: 途中で止まっても、あるコマを飛ばして続きから描ける。動画にできたらコマを消す(空き容量が少なかった)。乱数の種を固定してちらつきを抑える。

## 4. 使い回せるスクリプト

| ファイル | 何をするか | 使い回すときの注意 |
|---|---|---|
| `scripts/hz/util.py` | `MB`(メッシュの組み立て)、`stand_xf`、`frame_xf`、`text_obj`(壁に貼る文字。日本語はヒラギノ)、`coll` | そのまま使える。`text_obj` は文字をメッシュに直すので数十個なら軽い |
| `scripts/hz/layout.py` | 断面の区間の列 → 踏み面の一覧、通路、出入口、区間の引き算 | スタンドや劇場など、段のある建物ならそのまま |
| `scripts/hz/config.py` | JSON を読む。`field_lines()` はラインの位置 | — |
| `scripts/hz/materials.py` | 名前で取り出すマテリアル。`_noisy`(むら)、`emissive`(昼夜の切り替え)、芝の縞、菱形のタイル、レンガ | 色は sRGB(0〜255)で書いて `srgb()` でリニアに直す |
| `scripts/hz/sky.py` | `sun_vector`(方位と高度 → 向き)、`setup_day / setup_night / setup_render`、`_glare` | 敷地の +X の方位は config の `site.x_axis_azimuth_deg` |
| `scripts/hz/cameras.py` | 名前つきの角度、`look_at`、空中写真と重ねる正射影 `"map"` | `"map"` の縮尺は空中写真の画像の大きさに合わせて直す |
| `scripts/hz/seats.py` | 点の上に席を並べる、文字の判定 | — |
| `scripts/hz/details.py` | `rail_u`(手すり)、通路の段、出入口の箱 | — |
| `scripts/build.py` | 部品のモジュールを順に呼んで .blend を保存 | 部品を足すときは `STAGES` に名前を足す |
| `scripts/render.py` | 角度と昼夜を指定して静止画 | — |
| `scripts/compare.py` | 参考写真と同じ角度で描いて並べ、作者とライセンスの表も書く | `ITEMS` の表を差し替える |
| `scripts/orbit.py` | 一周の動画。続きから描ける。`--frames 0,225` で試し描き | 半径、高さ、始まりの角度は先頭の定数 |
| `run.sh` | build / check / stills / video / compare / all | 出力を `[` で始まる行とエラーだけに絞っている |
| `tools/osm_measure.py` | OSM の外形を、長辺に合わせた座標に直して出す | way の番号を差し替える |

空中写真の目盛りつき画像は、地理院タイルを curl で取り、ffmpeg でつないで回し、`drawgrid` で目盛りを重ねて作った(スクリプトにはしていない。作り方は reference.md の 3 章)。

## 5. 次に同じ種類の仕事をするときの順番

1. 公式の数字を集める(席数、台数、面積など「数えられるもの」は意外と出ている)。
2. 空中写真に目盛りを重ねた 1 枚を作り、規定の長さで縮尺を確かめる。
3. 大きさのわかっている物を 1 つ決め、写真から高さを測る。2 枚以上で確かめる。
4. 寸法の JSON と、断面 → 踏み面の仕組みを先に作る。
5. 大きな形 → 真上から重ねて確認 → 細部、の順。細部の前に必ず重ねる。
6. 参考写真と同じ角度のカメラを早めに作る(今回は⑨まで待ったが、③の時点で作っていれば屋根の高さや文字の大きさをもっと早く直せた)。
7. 段階ごとに: 描く → 自分で開く → 違いを書く → 直す → コミット → PROGRESS.md を更新 → push。
8. 残った違いは隠さず一覧にする。推定で作った所は、どこが推定かを数字と一緒に書く。
